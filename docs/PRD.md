## 1. 产品概述

### 1.1 定位
AI 辅助的长篇小说编辑器与知识库工具，不是聊天机器人。核心价值：把百万字级长篇变成可查询、可复核的结构化知识库。

### 1.2 平台
- 主平台：Windows 桌面。Flutter 前端（`flutter build windows`）+ FastAPI 后端本地运行（`run_backend.ps1`），前端固定连 `127.0.0.1:8000`。
- 次要平台：Android APK。同一份代码，保留构建能力，不再做真机验收驱动开发。
- 单机软件：无账号、无云同步、无自有服务端；唯一外部依赖是用户自配的模型 API。

### 1.3 目标用户与场景
网文作者、编辑、重度读者。坐在电脑前导入长篇小说，生成摘要/大纲/人物/关系/设定/时间线，做设定冲突检查，基于证据提问。

### 1.4 产品边界（不变）
- 不承诺完全准确；输出"疑似问题 + 证据"，不做最终裁决。
- 冲突检测与编辑判断必须保留人工复核。
- AI 结论必须尽可能附章节级证据；证据不足必须明说。

## 5. 数据模型

### 5.1 现有表（沿用）
novels、chapters、chunks、model_cache、settings、analysis_jobs、extracted_facts、review_actions。

### 5.2 extracted_facts 类型扩展
现有：character_profile、character_relationship。
新增：world_rule、faction、location、event（时间线条目）、setting_fact、setting_conflict。

### 5.3 每条事实必备字段
id、type、content、entities、chapter_id、chunk_id（可得时）、source_quote、confidence、status（active / updated / contradicted / pending_review）。

### 5.4 人物档案属性与原文证据（2026-07-21 用户明确追加）

人物档案不是"名字 + 一句话描述"。每个人物按属性结构化提取，**每项属性单独附带原文段落证据（可多段）**：

- 外貌描写：原文中关于长相、体态、服饰的段落。
- 性格：原文中体现言行、处世方式、情绪反应的段落。
- 身份 / 背景、能力、重要经历：同样附原文段落。
- 别名：沿用现有 aliases。

实现要求：

- evidence 为列表，**全部持久化，不得只保留第一条**（当前 `backend/app/main.py` 持久化时只取 `evidence[0]`，需修）。
- 每段证据带 chapter_id / chapter_title + source_quote；人物档案页按属性分组展示原文。
- 原文找不到依据的属性留空并标注"未提及"，禁止编造（幻觉红线）。

### 5.5 冲突记录字段
type、severity（high / medium / low）、title、entities、earlier_evidence、later_evidence、possible_explanation、model_judgment、confidence、status（pending_review / confirmed / dismissed / explained / watching）。

## 6. 长文本与检索架构

### 6.1 分层管线（永不整书单次请求）
导入 → 章节识别 → 长章 chunk 拆分 → chunk 摘要 → 章节摘要 → 弧摘要（约 200 章/弧）→ 全书大纲。结构化事实从 chunk / 章节分批抽取，增量合并。

### 6.2 两级检索（Q&A 与冲突检测共用）
1. 第一级：facts 库精确命中 + 章节摘要索引打分，定位候选章节；查询词用人物别名表扩展。
2. 第二级：只在候选章节内搜原文，截取引文。
3. 模型只能基于检索到的证据回答 / 判断。

### 6.3 分批抽取
人物、关系、设定、事件均按批次（每批 N 章）滚动抽取，增量合并去重；每批独立缓存 key，支持断点续跑。批次化会改变缓存 key 结构，实现时注意 key 含批次范围。

### 6.4 缓存规则
- key 格式沿用：`{app_version}:{prompt_version}:{model}:{task_type}:{schema_version}:{input_hash}`。
- 稳定前缀规则不变（系统提示 / schema / 策略 / 示例在前，变量数据在后）。
- 新增硬性规则：schema 校验失败或任务失败的结果不写入 model_cache；UI 展示缓存命中时区分"缓存的成功结果"。

### 6.5 任务可靠性
- 后端启动时清理僵尸 job（running 超时 → failed，可重试）。
- 所有长任务具备进度、取消、重试、失败态；批处理支持断点续跑。

## 7. 性能与规模目标（700 万字 / 3170 章基准）

- 导入 + 编码检测 + 章节识别：分钟级。
- 全书章节摘要：无人值守数小时（一次性成本，全部进缓存，可中断续跑，可并发提速）。
- 大纲 / 人物 / 关系 / 设定 / 时间线：基于摘要与分批抽取，单次模型请求输入有界（目标 ≤ 约 1-2 万字符）。
- Q&A：1-3 秒响应，附章节级引文。
- 重复运行同一任务：零重复模型调用。

## 8. 验收标准（桌面版）

1. `flutter build windows` 跑通，默认连 `127.0.0.1:8000`。
2. 700 万字中文 TXT 导入无乱码，章节识别准确。
3. "一键分析全书"可完成：进度可见、可取消、中断后续跑。
4. 全书大纲（分层）稳定生成；人物覆盖全书章节范围。
5. 设定页 / 时间线 / 冲突检测页有数据、带证据引文、冲突可复核（确认 / 驳回 / 已解释）。
6. Q&A 秒级响应，引文准确；检索命中别名与别称。
7. 失败任务不落缓存，重试真实重新调用；重复成功任务全部命中缓存。
8. 界面全中文；后端测试与前端测试全绿。

## 10. 风险与对策

- 模型输出不稳定：schema 校验 + 重试 + 本地 fallback 结果；失败不落缓存。
- API 成本：缓存优先；设置页展示累计调用统计。
- 抽取质量：一切事实带证据引文；pending_review 人工复核后才生效。
- 大书性能：所有全书级操作必须走分层 / 分批，禁止整书单次请求（代码评审红线）。
